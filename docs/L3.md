# L3：笔画骨架驱动的中文衬线后处理

这一篇说明 `scripts/l3_pipeline.py` 做了什么，以及**它没有做到什么**。它是一套可选的、可复现的后处理管线，不是第五档预设；仓库依然只有 `cjk`、`cjk-bold`、`multilingual`、`full` 四档构建，也依然不含任何字体二进制。

## 为什么要重做

早先有一版 `signature`，靠「x 方向极值 + 尖角」猜横画末端并做轮廓手术。逐字检查发现大量问题： detached 飞线、`文` 和 `永` 的点与撇被误判成横画、`國` 内部冒出斜刺、`一` 的三角顿笔被削成畸形方块，以及大字号下 FreeType 扫描溢出。那一版已整档撤回，本仓库不留任何痕迹。

根因是**轮廓里没有笔画信息**。只有点集，无法区分「横画末端」「点的收笔」「撇的尖端」「折笔拐角」。L3 的第一条改变，就是引入外部笔画骨架数据，让规则有据可依。

## 数据

`fetch` 在运行时下载 `hanzi-writer-data`（Make Me A Hanzi 的笔画 medians），解析出紧凑索引 `data/strokes.json`。实测：

- 索引含 **9,565 个汉字**、112,587 条笔画，平均每字 11.77 笔；
- 与 `cjk` 版 31,595 个码位求交，可命中 **9,565 个（30.27%）**，全部在 BMP，扩展区 B–I 无数据；
- 其余约 22,000 个码位**永远不被改动**，保持思源宋体原样。

`data/` 被 `.gitignore` 排除，索引不进仓库。该第三方数据的许可不由本仓库重新声明，读者在再分发任何索引或衍生结果前，应自行核实上游许可。

## 笔画分类

每条 median 按首尾方向、长度与中段折角分为 `H`（横）、`V`（竖）、`pie`（撇）、`na`（捺）、`dot`、`fold`（折）、`other`。**只有 `H` 参与处理**。这正是 `文`（首笔为点、`永` 全为点/折/撇捺）不会被误伤的原因。

实测 9,565 字中，有 172 字完全不含独立横画，自动跳过；「永」在其中。

## 变换的结构不变量

对每条横画，把 median 两端映射到该字的轮廓包围盒，在末端一个有限窗口内，把高于骨架中心线的点按 `PULL` 压向中心线：

- **不增删点、不改 flags、轮廓拓扑完全不变**；
- **x 坐标一个都不动**，只动有限窗口内的 y；
- 只动 `rise = y - Y` 落在 `(MIN_RISE, WINDOW_Y)` 的点。

这与上一版「把尖端一个点替换成三个点」有本质区别：没有新点，就没有脱离主体的飞线；没有 x 变化，就没有回折叠刺；拓扑不变，也就不可能触发大字号扫描溢出。

## 四档强度与逐字渲染审计

单靠「结构不变量」仍不足以保证工整，因为字形语义可能被破坏。所以每一个改动过的字都会被**重新渲染并与原版逐像素比对**，检查六类异常：

| 检查 | 捕捉什么 |
| --- | --- |
| `component_count` | 笔画被切断或粘连 |
| `hole_count` | 字怀被填死或多挖一个洞 |
| `hairline` | 出现小于 10 px 的脱离碎片（飞线） |
| `bbox_shift` | 字形外框位移超过 2 px |
| `blob` | 局部墨量暴涨超过 10%（畸形三角块） |
| `ink_delta` | 总墨量变化超过 22% |

任一异常即把**该字单独回滚**到未改动的思源宋体轮廓，其余字不受影响。

同一套规则跑四档强度，参数与结果：

| tag | PULL | 窗口 X/Y | 候选 | 通过 | 回滚 | 残差 |
| --- | --- | --- | --- | --- | --- | --- |
| `p45` | 0.45 | 240 / 170 | 8,709 | 6,165 | 2,544 | 0 |
| `p55` | 0.55 | 260 / 180 | 8,735 | 4,957 | 3,778 | 0 |
| `p65` | 0.65 | 280 / 190 | 8,760 | 3,834 | 4,926 | 0 |
| `p80` | 0.80 | 330 / 210 | 8,817 | 2,063 | 6,754 | 0 |

强度越大，视觉变化越明显，但通过率越低——这正是「规范」与「独特」之间的真实代价。

## 合并

`merge` 对每一个字形取**通过审计的最强版本**（`p80 > p65 > p55 > p45`），因为每个被取用的字形都已独立验证零缺陷，合并不会引入冲突。结果：

- **6,624 个字形**完成改动（占 31,724 字形的 20.9%）；
- 来源分布：p80 2,063 / p65 2,050 / p55 1,278 / p45 1,233；
- 合并后**全量复审 0 缺陷**；
- **720 个西文字形逐字节不变**，GSUB 19 / GPOS 2、2000 UPM、hhea 1985/-515、cmap 四张子表全部不变；
- 10 个常用字在 400 / 800 / 1000 px 渲染无溢出；
- 平均墨色比原版少 1.14%，整体观感几乎不变。

样张见 `assets/l3-comparison.png`：左列是已撤回的坏版（可见飞线与畸形末端），中列是原版，右列是 L3。

## 明确没有达成的部分

这一版解决了「不规范、有飞线」，但**没有解决「看起来独特」**。必须说清楚：

- 视觉变化非常温和。三角顿笔只是被压低、削平一点，斜坡仍在；放大看 `U+4E00` 的特写就能发现三列差别有限。平均墨色仅变化约 1%。
- 只覆盖 30.27% 的码位，且其中仅 6,624 字通过审计；扩展区生僻字、假名、韩文完全未处理（本管线只针对 `cjk` 版）。
- 没有字怀、中宫、轴线、字面宽度的逐字重设，也没有人工抽检 9,565 字；审计是像素级结构检查，不是设计审美判断。
- 它不是设计师逐字手绘的字体。要真正做出「按西文字怀与衬线语言重绘整套中文」的 L3 完全体，仍需笔画/部件级设计数据、分笔段的轮廓重建规则、以及通用规范汉字的人工校对回路。

把「规范」放在第一位，是这一版唯一的设计取舍。若你需要更强烈、更独特的字形，正确路径是接受更小覆盖率的人工重绘，而不是调大 `PULL`——调大只会让更多字被审计回滚。

## 复现

```bash
python3 scripts/build_cjk.py --latin inputs/AnthropicSerifWebText.ttf \
  --source-dir /usr/share/fonts/opentype/noto --preset cjk
python3 scripts/l3_pipeline.py fetch
for t in p45 p55 p65 p80; do
  python3 scripts/l3_pipeline.py build --tag $t
  python3 scripts/l3_pipeline.py audit --tag $t
done
python3 scripts/l3_pipeline.py merge --tags p80,p65,p55,p45
python3 scripts/verify.py build/SerifCJKExtension-L3.ttf --preset cjk
```

依赖：`fonttools`、`brotli`、`numpy`、`Pillow`、`scipy`。产物 `build/SerifCJKExtension-L3.ttf` 不进版本库。
